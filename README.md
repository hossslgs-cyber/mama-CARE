Overview
MamaCareis an offline-first maternal health tracking platform designed for frontline healthcare workers.
It enables CHWs to register patients, log visits, schedule appointments, run symptom-based triage decision
trees, and flag at-risk pregnancies — all without a constant internet connection. Data syncs to Supabase
when connectivity returns.
Target Users:
• Community Health Workers (CHWs) — Mobile-first, works offline, collects patient data
in the field
• Nurses—Dashboard view, analytics, reporting, patient oversight

ArchitecturePatterns
Pattern1:Offline-FirstDataFlow
Everydatamutationfollowsthisexactsequence:
async function createPatient(patientData: PatientInput) {
//1.Validateinput
const validated=patientSchema.parse(patientData);
//2.GenerateIDlocally
const patient: Patient={
id: crypto.randomUUID(),
...validated,
created_at: new Date().toISOString(),
updated_at: new Date().toISOString(),
synced_at: null,
is_deleted: false
};
//3.SavetoIndexedDBimmediately
await db.put('patients',patient);
//4.Add tosyncqueue
await addToSyncQueue({
id: crypto.randomUUID(),
table: 'patients',
operation: 'INSERT',
data: patient,
status: 'pending',
created_at: new Date().toISOString(),
retry_count: 0
});
//5.UpdateUIstateoptimistically
dispatch({ type: 'ADD_PATIENT',payload: patient});
//6.Triggersyncifonline
if (navigator.onLine){
syncEngine.sync();
}
return patient;
}

Authentication
Flow:
1. User enters phone number → Supabase sends OTP via SMS
2. User enters OTP code → Supabase verifies
3. JWT stored in httpOnly cookie named AUTH_COOKIE_NAME
4. Cookie payload: { role: 'chw' | 'nurse', expiresAt: number }
5. Role-based redirect: nurse → /nurse, chw → /chw
6. Expired cookies are auto-cleared, user redirected to /login
Demo Login: For hackathon/demo purposes, bypass OTP with demo buttons that set a mock cookie.
Offline-First Sync
How It Works
1. Local Storage: All data lives in IndexedDB first
2. Sync Queue: Every mutation is recorded in a sync queue table
3. Background Sync: When online, the sync engine processes the queue
4. Conflict Resolution: Last-write-wins with server timestamp check
5. Retry Logic: Failed syncs retry up to 3 times with exponential backoff
